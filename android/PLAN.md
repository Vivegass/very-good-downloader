# Very Good Downloader для Android (APK) — план

Составлен 13.11.2026 по коду `rust/src`, `rust/README.md` и `HANDOFF.md` (версия 1.11).

## Почему APK, а не сайт

В вебе всё, что связано с yt-dlp, пришлось бы держать на сервере. YouTube привязывает ссылку на поток к IP
(`ip=` в ссылке googlevideo), поэтому весь трафик видео шёл бы через сервер, а IP дата-центров YouTube блокирует
(«Sign in to confirm you're not a bot»). В APK всё работает на телефоне и с его IP: сервер не нужен, работают
вход в VK, раскладка по папкам и фоновая загрузка. Минус: нет iPhone и нет Google Play (раздавать через GitHub
Releases / Obtainium).

## Исходная точка

- **Ядро уже переносимое.** Всё делают `yt-dlp` и `ffmpeg` как отдельные процессы (`appinfo::command` / `tool()`,
  `spawn_lines`). Специфичного для Windows немного: `cfg(windows)` в `appinfo.rs`, `downloader.rs`, `ipc.rs`.
- **Главное препятствие — `curl.exe`.** Через него идут все HTTP-запросы: `music.rs`, `yandex_acc.rs`, `net.rs`,
  `spotify_app.rs`. На Android curl нет.
- **VK — «невидимый браузер» на WebView2** (`vk_web.rs` + `vk_agent.js`). На Android то же делается встроенным
  WebView, JS-код почти как есть.
- **Очередь (пауза, порядок, параллельная музыка) живёт в окне** `bin/vgd-gui.rs` (~2900 строк). Её надо вынести
  в ядро, чтобы ею пользовались и ПК, и телефон.

## Что поменялось на ПК после составления плана (учесть)

- **Имена видео без `[id]`** (коммит 2123f2e): id пишется в тег «комментарий» файла (`[id] ссылка`, `meta_comment`
  + `--embed-metadata`), читается `media::probe` → `video_id`; файл качается под именем с `[id]` и затем
  переименовывается (`strip_id_from_names`), одинаковые названия → «Название (2)». На Android это работает как есть —
  но `probe` идёт через `ffmpeg -i`, значит libffmpeg нужен и для «Разложить папку».
- **Поиск в журнале** — на телефоне тоже нужен (поле над журналом).
- **Уведомления от имени программы** (AppUserModelId) — только Windows; на Android свои уведомления службы.
- **Темы оформления** (сессия `themes`): темы — JSON в папке данных. На Android читать тот же формат и строить
  из него `ColorScheme` Compose, чтобы своя тема с ПК переносилась файлом. Среди встроенных — тема по Material
  Design 3 (поля названы по ролям M3, соответствие — в `rust/README.md`). На Android она — запасная схема для
  телефонов без Material You; основной вид описан в разделе «Оформление под телефон».
- **Фоновый режим и мгновенная загрузка** (сессия `background`): программа живёт в трее, ссылки качаются без окна,
  мьютекс от второй копии. На Android аналог — «Поделиться» сразу ставит в очередь службы без открытия экрана
  (прозрачная Activity, которая только отдаёт ссылку и закрывается) + уведомление «скачано».
  Очередь из `vgd-gui.rs` в `core/queue.rs` (этап 1) выносить уже с учётом фонового режима ПК.

## Архитектура

```
android/  (Kotlin + Jetpack Compose)  ← интерфейс, «Поделиться», уведомления, фоновая служба, WebView для VK
   │  UniFFI (Kotlin-обёртка генерируется автоматически)
   ▼
rust/core  (libvgd.so)  ← downloader, music, music_dl, mix, sort, fingerprint, settings, yandex_acc, очередь
   │  запуск процессов, как сейчас
   ▼
libpython.so + yt-dlp, libffmpeg.so, libqjs.so (QuickJS)  ← из youtubedl-android или своя сборка
```

Всё в этом же репозитории: рядом с `rust/` — папка `android/`.

## Что происходит с каждым модулем

| Модуль | На Android |
|---|---|
| `downloader.rs`, `downloader/mix.rs`, `downloader/music_dl.rs` | Остаются. Меняется только поиск инструментов и остановка процессов (на Linux — kill группы процессов вместо `taskkill`). |
| `sort.rs`, `fingerprint.rs`, `media.rs`, `settings.rs` | Без изменений. Папку данных передаёт Kotlin. |
| `music.rs`, `yandex_acc.rs`, `net.rs` | `curl.exe` → свой `http.rs` (`ureq` + rustls). На Windows тоже — уйдёт зависимость от curl. |
| `vk_web.rs` + `vk_agent.js` | Процесс с WebView2 → общий trait. На Android его реализует скрытый WebView на Kotlin с тем же `vk_agent.js`. |
| Плейлист VK (сейчас делает расширение, `extension/vk-main.js`) | Переносится в `vk_agent.js` командой «плейлист по ссылке». |
| Очередь из `vgd-gui.rs` | Новый модуль `core/queue.rs`. Окно на ПК переходит на него же. |
| `ipc.rs`, `watch.rs`, `spotify_app.rs`, трей, слежение за буфером | Не нужны. Вместо них «Поделиться» и плитка в шторке. |
| Куки из Firefox | Вход в YouTube в WebView → `cookies.txt`. Правило «куки только при повторе» остаётся. |

## Оформление под телефон

Цель: приложение выглядит «родным» на телефоне владельца (Pixel 6) и на популярных марках. По умолчанию стиль
выбирается по `Build.MANUFACTURER` / `Build.BRAND`; в настройках можно выбрать любой вручную (и любую тему-файл с ПК).

### Pixel и любой Android 12+: Material You (основной стиль)

- **Цвета из системы:** `dynamicDarkColorScheme(context)` / `dynamicLightColorScheme(context)` (Android 12+) —
  палитра берётся из обоев и «Обоев и стиля» на Pixel и меняется вместе с ними. Светлая/тёмная — как в системе.
  Ниже Android 12 — встроенная тема M3 с ПК (тот же JSON).
- **Иконка с цветом темы:** адаптивная иконка со слоем `<monochrome>` (Android 13+) — при включённых
  «Тематических значках» система сама красит её в цвета обоев. Отдельный монохромный рисунок стрелки ↓ нужен
  уже на этапе 3.
- **Вид Material 3 Expressive** (стиль Android 16): Compose Material 3 (1.4+, Expressive API — проверить
  стабильность на момент работы), Navigation Bar, кнопки и переключатели M3, форма и движение по M3.
  Уведомления и плитка в шторке тоже в цветах системы.

### Стили марок

Марка задаёт форму, раскладку и материалы; цвет акцента — из системы, где она его даёт (Samsung и Xiaomi на
Android 12+ тоже отдают Material You-палитру), иначе — из стиля. Описание — по свежим версиям прошивок
(ноябрь 2026); перед этапом снять скриншоты с живых телефонов или эмулятора и подогнать.

| Стиль | Кому по умолчанию | Чем отличается |
|---|---|---|
| **Material You** | Google, остальные марки | см. выше |
| **В духе One UI 8.5** | Samsung | Крупный заголовок экрана в верхней трети (содержимое ниже, под большой палец), спокойный однотонный фон, крупные скруглённые карточки, матовые полупрозрачные панели, плавающая панель вкладок-«таблетка» снизу |
| **В духе HyperOS 3** | Xiaomi, Redmi, POCO | «Стекло»: размытие и полупрозрачность, крупные скругления, плотные списки как в iOS; с HyperOS 3.1 — M3 Expressive-цвета |
| **В духе HarmonyOS 6 / MagicOS 10** | Huawei, Honor | Прозрачные слои и световые эффекты, мягкие тени, светлые воздушные карточки |
| **В духе iOS 26 (Liquid Glass)** | вручную (iPhone-версии нет) | Стеклянные элементы управления поверх содержимого, сгруппированные списки со вставкой, плавающая панель вкладок-«таблетка», крупные заголовки |

- **Реализация:** один набор экранов на Compose, стиль — объект `VgdStyle` (форма, отступы, вид навигации, вид
  карточек, материал «стекло/матовое/сплошное», типографика) поверх `MaterialTheme`. Те же параметры, что
  в раскладочных полях тем ПК (навигация, карточки, кнопки, фон), чтобы стиль можно было описать JSON-файлом.
- **Стекло и размытие:** `Modifier.blur` / `RenderEffect` есть только с Android 12; ниже — полупрозрачная
  заливка. Размытие на длинных списках проверить по скорости (Pixel 6 и средний Xiaomi).
- **Нельзя:** логотипы марок, фирменные шрифты (SF Pro по лицензии нельзя вне Apple; Samsung One, MiSans —
  проверить лицензию, по умолчанию системный шрифт), копии фирменных значков. Названия стилей — «в духе …».
- **Когда:** Material You и монохромная иконка — этап 3 (первая версия). Стили марок — этап 6, после основных
  функций.

## Этапы

### Этап 0. Проверить главные риски на настоящем телефоне (1–2 дня)

Голый прототип на Kotlin с youtubedl-android, без интерфейса. Проверить:

1. YouTube 1080p: VP9 + Opus склеиваются в MKV и сохраняются в `Download/`.
2. **JS-движок.** deno под Android не собирается; yt-dlp умеет QuickJS. Сравнить список форматов YouTube
   с `--js-runtimes quickjs` и без него.
3. **Сборка ffmpeg:** `ffmpeg -encoders`, `-filters`. Нужны `libx264` или `h264_mediacodec`, `zscale`, `tonemap`,
   `aac`. Если чего-то нет — своя сборка ffmpeg (+2–4 дня).
4. Rust-библиотека из `cargo-ndk` загружается и запускает `libffmpeg.so` из nativeLibraryDir (с Android 10
   запускать программы можно только оттуда).

**Готово, когда** видео 1080p с полным списком форматов скачано на реальном телефоне.

### Этап 1. Подготовить ядро, не сломав версию для ПК (3–5 дней)

1. Разделить `rust/` на workspace: `core` (без eframe, wry, tray, winreg), `desktop` (`vgd-gui`, `vgd`),
   `android` (cdylib).
2. `http.rs` на `ureq`; все вызовы `curl.exe` — через него. Прокси — из `HTTPS_PROXY`, как раньше.
3. Пути к инструментам и папке данных задаются при запуске (`appinfo::init(paths)`); на ПК поведение то же.
4. Linux-ветки: `free_gb` (через `statvfs`), остановка процессов.
5. Очередь из `vgd-gui.rs` → `core/queue.rs`.
6. VK — за общим trait.

**Готово, когда** `cargo test` проходит, а версия для ПК работает как 1.11 (можно выпустить как 1.12).

### Этап 2. Связать Rust и Kotlin (2–3 дня)

- UniFFI. Наружу: `init`, настройки (JSON, `settings.rs` без изменений), очередь (`add`, `pause`, `resume`,
  `move`, `cancel`), обработчики `on_progress` и `on_log`, `vk_search` (выполняет Kotlin через WebView).
- Gradle: `cargo-ndk` под `arm64-v8a`, плюс `x86_64` для эмулятора.

### Этап 3. Первая рабочая версия: видео (5–7 дней)

- **Ссылки:** «Поделиться» (`ACTION_SEND`), «Открыть с помощью» для youtube.com / youtu.be, выделенный текст
  (`ACTION_PROCESS_TEXT`), плитка в шторке «скачать из буфера».
- **Фон:** служба переднего плана `dataSync` с уведомлением о прогрессе, WakeLock + WifiLock. На Android 15
  у неё лимит 6 ч в сутки — по `onTimeout` очередь встаёт на паузу (пауза/продолжение уже есть в ядре).
- **Хранилище:** «Доступ ко всем файлам» (`MANAGE_EXTERNAL_STORAGE`, вне Google Play можно) — yt-dlp и `sort.rs`
  работают с обычными путями. По умолчанию `Download/Very Good Downloader/`. После каждого файла — MediaScanner.
- **Экраны:** «Скачать» (поле, очередь с ⏸/▶ и ↑↓), «Журнал», основные настройки (папка, разрешение, fps,
  субтитры, обложка, сортировка). Оформление — Material You (цвета из обоев, тематическая иконка); темы с ПК —
  выбором в настройках.

**Готово, когда** ссылка через «Поделиться» из приложения YouTube превращается в файл в `Эдиты/Канал/`.

### Этап 4. Музыка (4–6 дней)

- SoundCloud, YouTube Music; списки Spotify (ключ пользователя), Яндекса, Apple.
- Поиск замены, проверка по ISRC и по звуку (Deezer), теги, обложка, `.m3u8`, тексты LRCLIB, архив, копии
  треков в каждый плейлист.
- После этапа 1 тут почти всё — интерфейс.

### Этап 5. Аккаунты (4–6 дней)

- **VK:** экран входа (WebView с vk.com, сессия хранится в WebView), скрытый агент с `vk_agent.js`
  (поиск + плейлист по ссылке), звук прямо из VK.
- **Яндекс:** вход кодом (device flow) как есть, токен в файлах приложения.
- **YouTube** для 18+: вход в WebView → `cookies.txt`.

### Этап 6. Остальные функции (5–8 дней)

- **Копия для монтажа H.264:** `h264_mediacodec` или `libx264 -preset veryfast`. ProRes на телефоне скрыть.
- Фрагмент «с … до …», только звук, SponsorBlock, главы, микс → треки, пресеты и настройки отдельной ссылки.
- **Подписки:** периодическая задача WorkManager (например, раз в 6 ч, только по Wi-Fi) — та же логика, что `vgd sync`.
- «Разложить папку» (сначала план), редактор категорий (`topics.json`), «Обновить yt-dlp».
- Стили марок (раздел «Оформление под телефон»): Samsung, Xiaomi, Huawei/Honor, iOS-вид; автовыбор по марке.

### Этап 7. Выпуск (2–3 дня)

- Свой ключ подписи. **Не потерять** — иначе обновления не встанут поверх старой версии.
- GitHub Actions собирает APK по тегу. Только arm64, ~70–120 МБ.
- Проверка обновлений через GitHub Releases; ссылка для Obtainium в README.
- Проверить на Android 10, 13, 15, на Samsung и Xiaomi (Xiaomi убивает фон → запрос «не оптимизировать батарею»
  и подсказка в настройках).
- Обновить README и HANDOFF.

**Всего ~4–6 недель** по вечерам. Первая рабочая версия для видео — после этапа 3, примерно через 2 недели.

## Развилки (решает владелец)

| Вопрос | Рекомендация | Другой вариант |
|---|---|---|
| Стиль по умолчанию | **Стиль марки автоматически по производителю** (Pixel — Material You), сменить можно в настройках | Material You на всех, стили марок — только вручную |
| Интерфейс | **Kotlin + Compose**: нормальное поведение на Android, «Поделиться», служба, уведомления | Перенести egui: меньше нового кода, но на телефоне выглядит чуждо |

| Минимальная версия | **Android 8.0** | Android 10 |
| Где код | **Этот репозиторий**, `android/` | Отдельный репозиторий |

## Риски

- **ffmpeg в youtubedl-android может не содержать** `libx264` / `zscale` → своя сборка. Выяснится на этапе 0.
- **QuickJS может отдавать не все форматы YouTube.** Запасной вариант — Node.js под Android (как в Termux).
  Выяснится на этапе 0.
- **Лицензия.** youtubedl-android и Seal — GPL-3.0; если брать их код, APK тоже под GPL. Репозиторий и так
  публичный, но лицензию стоит выбрать явно.
- **Предупреждения при установке.** Play Protect ругается на APK «из неизвестного источника», как SmartScreen
  на Windows: «Всё равно установить».
- **YouTube регулярно ломает yt-dlp.** Кнопка обновления yt-dlp нужна с первой версии, а не на этапе 6.
